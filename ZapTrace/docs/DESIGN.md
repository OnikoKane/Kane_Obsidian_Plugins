## 0. 一页速览

- **一句话**：ZapTrace 让数学题以「Markdown 题卡」的形式留在笔记里，在 Obsidian 内完成 **先作答 → 看答案 → 四档回忆评分 → 安排下次复习** 的闭环，所有状态本地保存，**绝不改写你的原文**。
- **三个面**：左「练习」、中「题集」、右「复习」，一个工作台视图内切换。
- **一条铁律**：题干/答案/笔记/标签只存在于 Markdown；收藏、评分、到期日只存在于 `data.json`。两边不互相写回。
- **不做**：PDF 导入、批注、AI 生成、复杂组卷、仪表盘（见 §13）。

## 1. 产品定位（克制的边界）

### 1.1 一句话定位

> 一个**只做数学刷题与间隔复习**的 Obsidian 插件：把笔记里的题卡变成可练、可评分、可排期的题目，其他什么都不做。

### 1.2 是什么 / 不是什么

| 是 | 不是 |
| --- | --- |
| Markdown 题卡的**解析器 + 渲染器** | 题库导入工具（不解析 PDF/图片/Word） |
| 单题的**作答—揭晓—评分**流程 | 笔记/批注工具（不写批注、不改正文） |
| 基于四档评分的**确定性间隔复习** | 智能学习助手（不调用任何大模型） |
| 全库题卡的**索引与筛选浏览** | 数据看板（不做统计图表、热力图、排行榜） |
| `data.json` 里的**本地状态** | 云服务 / 账号 / 同步后端 |

### 1.3 三条主线与闭环

```
① 记录线  Markdown 题卡（人写 / 模板插入）  ──解析──►  内存索引
                                                     │
② 练习线  选一题 → 只看题干 → 作答 → 揭晓答案/笔记 → 四档评分
                                                     │
③ 复习线  评分 ──写──► data.json 状态（step / due / 时间记录）
                          │
                          └── 到期 ──► 今日复习队列 ──► 回到 ②
```

- **参考视频的核心**逐条落到本设计：先作答再看答案（§7.1）、四档回忆评分（§8）、安排下次复习（§8.2）、保留出处（`source` 字段，§3.2）、数据本地 Markdown（§4.3、§9）。

### 1.4 三条克制的产品决策（先定下来，避免越做越重）

1. **状态外置**：答案折叠、Star、评分、到期全部是「读取 Markdown + 读写 data.json」，Markdown 永远干净、可 diff、可 git。
2. **确定性优先于「智能」**：复习排期用固定转移表（§8.2），不用 FSRS/SM-2 参数，可被单元测试逐格验证。
3. **先交付一个面**：首版把交互收敛到「阅读视图 + 独立工作台面板」，实时预览只做降级（§5.2），不追求编辑器内全交互。

## 2. 信息架构与三栏工作台

### 2.1 布局

ZapTrace 主视图是一个 **ItemView**（右侧主区域打开的整页视图），三栏 CSS Grid：

```
┌───────────────────────────────────────────────────────────────────────┐
│  ZapTrace  [今日复习 12]                        [⚙ 设置] [⟳ 重建索引]  │  44px 顶栏
├──────────────────┬──────────────────────────────┬─────────────────────┤
│  ① 练习          │  ② 题集                      │  ③ 复习             │
│  Practice        │  Library                     │  Review             │
│                  │  ┌─ 搜索 / 科目 / 标签 / 排序 ┐│  今日到期 · 按科目   │
│  3 / 12          │  └───────────────────────────┘│  ▸ 高等数学  6       │
│  ┌────────────┐  │  ★ 求 f(x)=x² 在 x=1 的导数  │  ▸ 线性代数  4       │
│  │  题干      │  │    高等数学 · 导数 · 明天到期 │  ▸ 概率论    2       │
│  │  ...       │  │  ★ 判断级数收敛…             │  ─────────────      │
│  └────────────┘  │    高等数学 · 级数 · 已到期   │  时间记录            │
│  [显示答案]      │  ...                          │  11-02 14:10 想起    │
│  （揭晓后）      │                               │  ...                │
│  [答案][笔记]    │                               │  [按科目组卷]        │
│  [忘记][困难]    │                               │                     │
│  [想起][秒答]    │                               │                     │
└──────────────────┴──────────────────────────────┴─────────────────────┘
```

- 列宽：`minmax(320px, 1.1fr) / minmax(280px, 1fr) / minmax(280px, 0.9fr)`；三栏各自独立滚动。
- 窄屏（< 900px）收起为单栏 + 底部三段切换（§10.10）。
- **不新增全局主题**：ZapTrace 只在自身面板内使用令牌（§10.1），不覆盖 Obsidian 正文排版（那是 MubuStyle 的职责）。

### 2.2 内容与状态的数据流

```
Vault（*.md）
   │  vault.getMarkdownFiles() + vault.cachedRead()
   ▼
Parser（解析 ```zaptrace 块）
   │  产出 QuestionCard { qid, stem, answer, notes, tags, source, subject, line… }
   ▼
Index（内存，纯派生，可随时重建）
   │  Map<instanceKey, Card>（instanceKey = 相对路径#块序号）；qid 仅作 data.json 状态键
   ├──────────────► ② 题集（筛选/搜索）
   └──────────────► ③ 复习（按 subject 分组）
                          │ 用户评分
                          ▼
                 Store（data.json，唯一持久状态）
                 step / due / star / reviews / reviewLog
                          │
                          └── 回填到 ① 练习/③ 复习 的到期判断
```

- **派生 vs 持久**：卡片正文永远从文件实时解析，索引是「临时视图」；`data.json` 只存状态与最少量缓存字段（§9.4）。
- 监听 `metadataCache` 的 `changed`/`resolved`，去抖 500ms 重建受影响文件或全量（首版可全量，见 §6.1）。

## 3. 题目 Markdown 语法

### 3.1 总则

- 用一个 **围栏代码块**（fenced code block）承载一道题，语言标记固定为 `zaptrace`。
- 代码块内部结构：**可选头部键值区** + **正文分节**（`### 题干` 等）。头部**只有在第一个非空行是合法 `key:` 行时才可能存在**，并以一条独立 `---` 结束；否则从第一行起整段都是正文（题干里的 `---` 永远安全，见 §3.2）。
- 代码块内部是**纯文本**，先解析，再把每一节文本交给 Obsidian 的 `MarkdownRenderer.render()` 渲染，因此 **LaTeX（`$…$` / `$$…$$`）、Markdown、列表、表格全部可用**。
- **围栏长度规则**：若题干/答案里需要写三反引号代码块，最外层必须用 **四个及以上反引号**（CommonMark 规则：外层围栏长于内部任意围栏）。这样「答案里含代码」也不会截断题卡。

### 3.2 头部字段（键值区）

**头部识别（H3，唯一规则）**：

1. 先跳过块首空行；看**第一个非空行**。
2. **仅当它匹配 `^[A-Za-z][A-Za-z0-9_-]*\s*:`**（即首行就是一条 `key:` 行）时，才进入「头部态」；否则**整块从第一行起就是正文**，不剥离任何「头部」。
3. 头部态内逐行 `key: value`，`value` 取**第一个冒号之后**的全部内容（允许内部含冒号，如 `source: 高数 p.86: 例3`）。**不支持嵌套**。
4. 头部态遇到**第一条独立 `---`**即结束头部，之后全部是正文。
5. 头部态遇到**不符合 `key:` 的行**（含空行后跟正文）：**立即结束头部，该行起全部归正文**（绝不丢弃）。若还没遇到 `---`，同样以该行为正文起点。
6. 块的第一个非空行是 `---` 或标题行 → 无头部，整块都是正文。

> 这样「无头部、题干里含 Markdown 水平线 `---`」的题卡不会把 `---` 前面的题干误当头部吞掉。

| key | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `id` | 否 | `[A-Za-z0-9._:-]+` | 稳定 ID，**强烈建议手写**（§4.1）。缺省时自动派生 |
| `subject` | 否 | 短文本 | 主要科目，用于题集/复习分组；缺省取所在文件夹名或 `未分类` |
| `tags` | 否 | 逗号或顿号分隔 | 如 `导数, 极限, 易错`；去空白、去重 |
| `source` | 否 | 单行文本 | **出处**，如 `高等数学 第七版 p.86`；做题卡底部小字 |
| `star` | 否 | `true`/`false` | **仅作首次收录的初始收藏值**；之后以 data.json 为准（§9.3） |
| `difficulty` | 否 | `1`–`5` | 可选，首版只展示不参与排期 |
| `pdf` | 否 | 单行文本 | **PDF 来源预留字段**：首版只存不展示筛选，见 §6.2 |
| 其他 | 否 | 任意 | 未知键保留进 `extra`，不报错、丢弃前不修改原文 |

### 3.3 正文分节

用三个及以上井号 + 固定标题开启一节，内容持续到下一个分节标题或代码块结尾。匹配前先对整块做**公共缩进 dedent**，再用宽松正则认标题：`^#{3,}\s*(题干|答案|个人笔记|AI\s*笔记)\s*$`（容忍 `###题干` 无空格、尾随空格、整体缩进）。

| 分节标题 | 必填 | 渲染为 |
| --- | --- | --- |
| `### 题干` | 是 | 题卡正文（始终可见） |
| `### 答案` | 是 | 默认折叠的「答案」折块 |
| `### 个人笔记` | 否 | 默认折叠的「个人笔记」折块 |
| `### AI 笔记` | 否 | 默认折叠的「AI 笔记」折块（**纯文本字段，插件不生成**） |

- 节内允许任意 Markdown/LaTeX/多行；节首尾空行自动裁剪。
- 顺序无关，允许缺省 `### 个人笔记` / `### AI 笔记`。
- 若完全没有分节标题：整段正文当题干，答案缺失 → 标红提示（§3.5）。
- 出现分节标题但**缺 `### 题干`**（如只有 `### 答案`）→ 语法错误，题干区显示「缺少题干分节」并给行号。
- 出现分节标题但**缺 `### 答案`** → 语法错误，答案区显示「缺少答案分节」并给行号。

### 3.4 完整示例

````markdown
```zaptrace
id: 2024-gaoshu-deriv-001
subject: 高等数学
tags: 导数, 极限, 易错
source: 高等数学 第七版 p.86 例 3
difficulty: 3
---

### 题干

求 $f(x)=x^{2}$ 在 $x=1$ 处的导数，并写出定义式。

$$
\lim_{\Delta x\to 0}\frac{(1+\Delta x)^{2}-1}{\Delta x}
$$

### 答案

$f'(1)=2$。

先写增量比 $\dfrac{\Delta y}{\Delta x}=2+\Delta x$，再令 $\Delta x\to 0$。

### 个人笔记

- 关键是别漏掉「先增量比、再取极限」。
- 我上次错在直接对 $x^2$ 求导后代入，跳过了定义。

### AI 笔记

> 常见错误：把导数当成函数值之差。可用切线斜率直观校验。
```
````

### 3.5 边界与错误处理

| 情况 | 行为 |
| --- | --- |
| 缺 `### 答案`（有分节） | 卡片正常显示题干，答案区显示「⚠ 缺少答案分节 · 第 N 行」；不阻断其他卡片 |
| 缺 `### 题干` 但有其他分节 | 语法错误：题干区显示「⚠ 缺少题干分节 · 第 N 行」，答案照常折叠；不阻断其他卡片（C2） |
| 缺任何分节 | 整段当题干，答案标缺失（同上） |
| 无头部、题干含 `---` | `---` **留在题干里**，不做头部剥离（H3 回归） |
| 头部 `key` 拼错 | 当作 `extra` 保留，UI 不报错；调试模式下提示 |
| 头部态出现非 `key:` 行 | 立即结束头部，该行起全部归正文（不丢弃） |
| **手写 `id` 重复** | **重复即冲突**：一律按 §4.4 的确定性规则隔离，**不依赖文件枚举顺序、不修改文件**（H2） |
| **自动 hash 重复（同文两题）** | 视为同一 base、按 §4.4 规则各自派生唯一 qid，两卡独立、状态互不影响（H1） |
| 围栏内含 ` ``` ` | 要求外层用 ` ```` `；否则按 CommonMark 自然截断（文档里提示正确写法） |
| 空代码块 | 忽略，不进入索引 |

### 3.6 为什么不用「纯 YAML frontmatter」或「行内标记」

- **不用 YAML**：数学正文大量出现 `:`、`|`、`>`、`\`，用 YAML 的 `|` 块标量极易因缩进/制表符出错；自写的「单行 `key: value` + `---`」解析零依赖、错误可定位。
- **不用行内标记（如 `{{答案}}`）**：题干里出现花括号（集合、LaTeX）会冲突；分节标题对写作者最直观、对解析器最稳。
- **代价**：写在代码块里，Obsidian 源码模式下看到的是代码。这是有意的——首版用阅读视图/工作台渲染（§5），源码模式保留可读原文。

## 4. 题目 ID 与「原文不被写回污染」

### 4.1 两个键：instanceKey（索引）与 qid（状态）

- **instanceKey = `${相对路径}#${块序号}`**：`块序号` 是该文件内 `zaptrace` 块的 0 起始出现序号。这是**内存索引的唯一键**，用于渲染/筛选/练习定位，保证「同文重复题是两张不同的卡」。
- **qid**：只作 `data.json.questions[qid]` 的**状态键**，由下面规则确定性派生。
- 二者分离：索引**绝不以 qid 作 Map 键**；题集/练习都用 Card 实例（同时携带 instanceKey 与 qid）。

**qid 派生规则（确定性，不依赖文件枚举顺序）**：

```
base(card) = 头部合法 id 存在 ? trim(id)
                              : "auto:" + hash(canonicalStem) 前 12 位 hex

按 base 分组；组内按 instanceKey 排序（路径字典序，其次块序号数值）：
  · 组内只有 1 张卡     → qid = base
  · 组内 >1 张卡（冲突） → 排序最靠前的卡 qid = base（规范持有者）
                          其余卡 qid = base + "~" + hash(instanceKey) 前 6 位
                          并标 duplicateOf = base、isDuplicate = true
```

- 关键：分组排序**只看 instanceKey（路径字符串 + 块序号数值）**，与 `getMarkdownFiles()` 返回顺序、异步读完顺序无关 → 同一批文件无论枚举顺序如何，分配结果完全一致（H2）。
- `hash()` 用 `src/core/hash.ts` 的**纯同步实现**（FNV-1a 64 位或内置 SHA-1），**不用异步 `crypto.subtle`**，保证解析可同步、可 `node:test`（C16）。
- 推荐仍手写 `id`：跨改题干/改答案/挪文件都稳定。自动 ID 只依赖题干（不含答案/笔记/标签），改题干换 ID、旧记录 `orphaned` 保留（§4.4）。

### 4.2 派生 ID 的规范化

对 `### 题干` 文本做，再取哈希：

1. Unicode **NFC** 归一；
2. 每行去行尾空白；
3. 行内连续空格/制表符压成一个空格；
4. 去掉首尾空行；
5. 以 `\n` 连接，UTF-8 编码，纯同步 `hash()`，取前 12 位 hex。

> 只规范化「不影响语义的空白」，不做大小写折叠（数学符号大小写有别）。

### 4.3 只读策略（核心约束）

ZapTrace 对用户笔记的写入边界：

| 操作 | 是否写 Markdown | 说明 |
| --- | --- | --- |
| 索引/浏览/练习/评分/复习 | **绝不写** | 全部读写 `data.json` |
| 点 Star | 不写 | 只写 `data.json.questions[qid].star` |
| 修改题卡内容 | 不写 | 由用户在编辑器里改；插件只在下一次索引时重读 |
| 「插入题卡模板」命令 | **写入**（用户显式触发） | 在光标处插入空模板，属于「新建内容」，不是「状态写回」 |
| 修重复 ID | 不写 | 只在 UI 提示，用户自行改 |

> 因此：**文本区永远不会有插件自动追加的 `<!-- zaptrace:... -->`、行尾标记、隐藏注释**；git 历史里只有你真正改的内容。

### 4.4 编辑 / 重命名 / 重复

- **改题干**（自动 ID）：旧 qid 从索引消失；`data.json` 里该记录标 `orphaned=true`（保留 `due`/`reviews`），题集「孤儿」筛选项可见、可一键「迁移状态到…」或删除。**不自动删除**。
- **改答案/笔记/标签**：qid 不变（自动 ID 只看题干），状态全保留。
- **挪文件**：qid 不变；`questions[qid].file` 缓存更新为最后已知路径，仅用于展示。
- **手写 id 重复（H2）**：**不做「先到先得」**。按 §4.1 分组、按 instanceKey 确定性排序：路径字典序最靠前者持有原 id，其余降级为 `base~hash(instanceKey)` 并标 `isDuplicate`，题集显示 `!重复ID`。结果只取决于文件路径与块序号，与枚举顺序无关；用户改名后冲突自动消失。
- **同文重复题（H1）**：自动 ID 因题干相同而有同一 base，按 §4.1 同样分组消歧，得到两个（或多个）互不相同的 qid；各卡独立 `star/step/due/reviews`，评分不串题。题集并列显示两张卡，标 `相同题干` 提示。
- **冲突集合变化时**：若新增的重复卡在字典序上更靠前，规范持有者可能变化；被替换者的旧状态会失去对应 qid 而标 `orphaned`（保留不删），UI 提示「ID 冲突：已隔离」。这是确定性、可解释的代价；**绝不静默把状态挂到另一道题**。
- **不做**：自动把状态迁到另一 id 的操作；只提供手动「孤儿 → 迁移」入口。

## 5. 渲染：阅读视图 vs 实时预览

### 5.1 首版可靠方案：阅读视图（Reading View）

用 Obsidian 官方 API `registerMarkdownCodeBlockProcessor("zaptrace", handler)`，在**阅读视图**把代码块替换为完整交互卡片：

- 卡片 DOM 由 handler 构建，`MarkdownRenderer.render(app, sectionText, hostEl, sourcePath, component)` 渲染每节（支持 LaTeX）；组件统一用 `component.addChild` 注册，卸载时自动清理。
- 支持：Star 切换、答案折叠展开（**默认折叠**）、个人/AI 笔记折叠、点击「练习此卡」在工作台左栏打开。
- 答案区**懒渲染**：首次展开时才 `MarkdownRenderer.render`，避免整页题卡的公式一次性全渲染（性能，§5.3）。

> 为什么这是可靠方案：`registerMarkdownCodeBlockProcessor` 是稳定公开 API，阅读视图为静态渲染，DOM 不会被编辑器高频重建，折叠/Star 的点击状态不会闪回。

### 5.2 实时预览（Live Preview）降级方案

- 各 Obsidian 版本对 LP 里代码块处理器的调用行为不一致。**先做运行时 feature-detect**（读取 `MarkdownView.getMode()` 或当前视图状态）：仅阅读视图渲染完整卡片；LP 一律只渲染只读缩略卡或直接保留源码，避免「既渲染缩略卡又保留源码」的双份（C14）。
- 首版策略：Live Preview 中渲染为**只读缩略卡**（显示题干前 3 行 + 「在阅读视图/工作台打开」按钮），**不承诺**在 LP 内完成评分流程。
- 评分/复习**只在工作台面板与阅读视图**进行；提供命令「在阅读视图打开当前笔记」与设置项 `livePreview: compact | source`。
- 若后续要做 LP 全交互（v2），用 CM6 `ViewPlugin` + `Decoration.replace` 包裹**非光标所在**的题卡为 widget；属明确后续项，不在首版。

### 5.3 兜底与性能

- **兜底**：processor 未生效（老版本/主题冲突）时，原始代码块仍是合法 Markdown，可读、可复制——**优雅降级**。
- 性能：
  - 首屏只渲染视口内的卡片答案（懒渲染 + `IntersectionObserver` 可选）。
  - 单文件题卡数 > 100 时，折叠态一律不渲染答案 DOM。

### 5.4 安全

- 渲染用户文本走 `MarkdownRenderer.render`；**禁止 `innerHTML` 拼接原始文本**。
- 若需要在卡片上放少量内联 HTML（如标题），只用 `el.createEl` / `setText`，绝不用 `style` 属性依赖（Obsidian 消毒器对 class 友好，对 style 不保证）。
- **原始 HTML 信任模型（C10）**：题卡内容视为**作者可信的本地输入**；`MarkdownRenderer` 对原始 HTML 的消毒随 Obsidian 版本而变，不保证强隔离。设置项 `sanitize: trusted | strict`：`strict` 时用 DOMPurify 或禁用原始 HTML；v0.1 默认 `trusted`，并在文档中明示该前提。

## 7. 练习与复习闭环

### 7.1 练习流程（先作答再看答案）

1. **选题**：题集点行 / 复习队列 / 命令「随机练一题」/ 卡片上的「练习此卡」。
2. **只显示题干（state = viewing）**：左栏顶部显示 `进度 i / N`，正文只渲染 `### 题干`；答案与笔记**完全隐藏**（DOM 不注入）。**此态评分条不渲染进 DOM、`1`–`4` 键盘处理器 early-return、不存在任何写 `data.json` 的路径**（H4）。
3. **作答**：用户心里/纸上/自备草稿作答（首版不强制输入作答文本，保持克制；可选设置「需填写作答后才能看答案」默认关）。
4. **揭晓（state = revealed）**：点「显示答案」→ 渲染答案 + 个人笔记（折叠）+ AI 笔记（折叠）→ **此时才出现**四档评分条，键盘 `1`–`4` 自此刻起生效。
5. **评分（state = rated）**：点/按键选四档之一 → 写入状态 → 顶部提示「已安排：11-05 复习」→ 自动进入下一题；`rated` 后评分条禁用，防重复写。
6. **结束**：队列走完显示小结「本次 12 题，忘记 2 / 困难 3 / 想起 6 / 秒答 1」。

> 「先作答」靠**默认折叠 + 不预渲染答案 DOM** 保证，不靠文字提醒；评分门禁靠**三态状态机**（`viewing → revealed → rated`），不靠 `aria-disabled` 这类软提示。

### 7.2 复习面板（右栏）

- **今日到期**：`due <= 今天` 的题（含今天到期与已过期，按 §6.2 细分展示），按 `subject` 分组，显示每组数量；点组展开题列表。
- **开始组卷**：按当前选中科目生成今日练习队列（§7.4）。
- **时间记录**：最近练习事件列表（§7.3），默认显示今天，可展开近 7 天。
- **无到期**：显示「今日无到期」+「随机练一题」按钮。
- 每日上限：`settings.dailyReviewLimit`（默认 20；**与学习系统 `review-rules.md` 的「每日 8 条」不同，ZapTrace 为独立插件、不复用该值**，C5）；超出的到期题显示「+N 顺延」，不强制清空。

### 7.3 时间记录

每次评分写一条 `reviewLog` 事件：

```json
{ "qid": "2024-gaoshu-deriv-001", "at": "2026-11-02T14:10:33+08:00",
  "rating": "good", "elapsedMs": 42000, "subject": "高等数学" }
```

- `at`：ISO 8601 含本地偏移，用于「时间记录」与耗时统计。
- `elapsedMs`：从「显示题干」到「点评分」的时长（不含选卡等待），可选，失败记 `null`。
- 右栏按日期分组展示 `HH:mm 评分标签`；点条目可跳到该题。
- `reviewLog` 全局裁剪到最近 5000 条（§9.6）。

### 7.4 按主要科目组卷（简单规则，非智能）

「组卷」= 生成一个**有序练习队列**，规则固定可测：

1. 取 `subject === 选中科目` 且 `due <= 今天` 的题；
2. 排序：`due` 升序 → `lapses`（忘记次数）降序 → `qid` 字典序（稳定）；
3. 截断到 `dailyReviewLimit`；
4. 若为空，提示「该科目今日无到期」，给「练 5 道未练题」入口（`step === -1` 的题按字典序取前 5）。

> 不做：跨科目自动配比、难度加权、遗忘曲线拟合。这是有意克制。

### 7.5 暂停与跳过

- 练习中「跳过」：本题今日不再出现（临时集合，不写 data.json），队列继续。
- 「今天不再提醒某题」：可选写入 `snoozeUntil`（v0.2），首版不做。

## 8. 四档回忆评分 → 间隔的确定规则

### 8.1 四档定义

| 档位 | key | 语义 | 用户心智 |
| --- | --- | --- | --- |
| 忘记 | `again` | 完全想不起/做错 | 需要尽快再见 |
| 困难 | `hard` | 想起来很吃力/勉强做对 | 降一档 |
| 想起 | `good` | 正常回忆/顺利做对 | 进一档 |
| 秒答 | `easy` | 立刻想起/秒解 | 进两档 |

### 8.2 状态机：`step` 与转移表

- 每题维护整数 `step ∈ {-1, 0, 1, 2, 3, 4}`，初始 `-1`（从未练习）。**加载与评分前统一 `step = clamp(step, -1, 4)`**（防手改成 5/−2 导致 `STEP_DAYS[max(step,0)]` 越界产生 `NaN` 日期，C3）。
- 间隔阶梯 `STEP_DAYS = [1, 3, 7, 15, 30]`，`STEP_DAYS[max(step,0)]` 即本次间隔天数。
- **转移表（唯一事实来源，实现须照此）**：

| 当前 step | 忘记 `again` | 困难 `hard` | 想起 `good` | 秒答 `easy` |
| --- | --- | --- | --- | --- |
| **-1（新题）** | → -1 / 1 天 | → -1 / 1 天 | → 0 / 1 天 | → 1 / 3 天 |
| **0** | → -1 / 1 天 | → -1 / 1 天 | → 1 / 3 天 | → 2 / 7 天 |
| **1** | → -1 / 1 天 | → 0 / 1 天 | → 2 / 7 天 | → 3 / 15 天 |
| **2** | → -1 / 1 天 | → 1 / 3 天 | → 3 / 15 天 | → 4 / 30 天 |
| **3** | → -1 / 1 天 | → 2 / 7 天 | → 4 / 30 天 | → 4 / 30 天 |
| **4** | → -1 / 1 天 | → 3 / 15 天 | → 4 / 30 天 | → 4 / 30 天 |

公式（等价实现）：

```
after.again : step' = -1;                          days = 1
after.hard  : step' = max(-1, step - 1);           days = STEP_DAYS[max(step',0)]
after.good  : step' = min(4, step + 1);            days = STEP_DAYS[max(step',0)]
after.easy  : step' = min(4, step + 2);            days = STEP_DAYS[max(step',0)]
```

- 忘记永远把 `lapses += 1`，并重置 `step = -1`。
- 首次（step=-1）`想起` → 1 天，与 `_system/review-rules.md`「首次学会 1 天」一致；连续 `想起` 为 1→3→7→15→30。

### 8.3 日期边界与计算

- **时区**：默认用设备本地时区日历日；设置 `dateMode: fixed` 时固定 `Asia/Shanghai`。统一用 Obsidian 内置 `moment`。
- **粒度**：`due` 只是日期 `YYYY-MM-DD`，无时分。
- **今天**：`today = moment().format("YYYY-MM-DD")`（本地 00:00 边界）。
- **计算**：`due = moment(today, "YYYY-MM-DD").add(days, "day").format("YYYY-MM-DD")`。
- **到期判定**：字符串比较 `due <= today`（ISO 日期可直接字典序）；`due` 缺失视为 `未练`（不计到期，但可在题集「未练」筛出）。**细分**：`今天到期 = (due == today)`、`已到期 = (due < today)`，筛选（§6.2）与队列（§7.2）共用同一口径（C4）。
- **不产生当日循环**：`again` 给出 `days = 1`，即最早明天，绝不会今天马上又到期（避免打开即到期死循环）。用户当天想重练，可主动「再练一次」，此时以当前 `step` 重新评一次即可。
- **月末/年末/闰年/夏令时**：全部交给 `moment.add(days,"day")` 处理；禁止手写「+86400000 毫秒」。
- **跨天练习**：若用户在 23:59 开始、00:01 评分，以**评分时刻**的日历日作为 `today`。

### 8.4 示例序列

新题连续「想起」：`step -1 → 0 (1d) → 1 (3d) → 2 (7d) → 3 (15d) → 4 (30d)`。
第 3 次时改「困难」：`step 2 → hard → 1 → 3 天`，`lapses` 不增。
任一次「忘记」：`step → -1，1 天，lapses+1`。

### 8.5 与学习系统 review-rules 的关系

- ZapTrace 的 1/3/7/15 与 `_system/review-rules.md` 的「首次 1 天 / 连续 2 次 3 天 / 3 次 7 天 / 4 次 15 天」同构，额外补一档 30 天并加入「困难/秒答」的加减档。
- ZapTrace **不读取** `_kb`/`_log`，是独立插件；此处只保证心智一致，便于两边数据互相理解。

## 9. data.json 数据结构与迁移

### 9.1 存储位置与原则

- 位置：`<vault>/.obsidian/plugins/zaptrace/data.json`，由 `this.saveData()` / `this.loadData()` 管理。
- 原则：**只存状态**，不复制题干/答案全文；未知字段**保留**（前向兼容）；任何迁移前**先备份**。

### 9.2 结构示例

```json
{
  "schemaVersion": 1,
  "settings": {
    "cardFolder": "",
    "defaultSubject": "",
    "dateMode": "local",
    "dailyReviewLimit": 20,
    "requireAnswerBeforeReveal": false,
    "livePreview": "compact",
    "theme": "auto"
  },
  "questions": {
    "2024-gaoshu-deriv-001": {
      "id": "2024-gaoshu-deriv-001",
      "star": true,
      "subject": "高等数学",
      "tags": ["导数", "极限"],
      "source": "高等数学 第七版 p.86 例 3",
      "file": "高数/第二章.md",
      "stemHash": "a1b2c3d4e5f6",
      "firstSeenAt": "2026-11-01T09:00:00+08:00",
      "lastSeenAt": "2026-11-02T14:10:33+08:00",
      "step": 1,
      "due": "2026-11-05",
      "lapses": 1,
      "reviews": [
        { "at": "2026-11-01T09:00:00+08:00", "rating": "good", "days": 1, "due": "2026-11-02" },
        { "at": "2026-11-02T14:10:33+08:00", "rating": "good", "days": 3, "due": "2026-11-05" }
      ],
      "orphaned": false
    }
  },
  "reviewLog": [
    { "qid": "2024-gaoshu-deriv-001", "at": "2026-11-02T14:10:33+08:00",
      "rating": "good", "elapsedMs": 42000, "subject": "高等数学" }
  ],
  "meta": { "lastScanAt": "2026-11-02T14:12:00+08:00", "pluginVersion": "0.1.0" }
}
```

### 9.3 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schemaVersion` | int | 当前 1；迁移依据 |
| `settings.*` | — | 用户设置（§12） |
| `questions.<qid>.star` | bool | 收藏状态；**首次收录**时若卡片 `star: true` 则置 true，之后以此为准 |
| `questions.<qid>.subject/tags/source` | — | **缓存**，每次索引随卡片刷新；用于无文件读取时也能分组展示 |
| `questions.<qid>.file` | string | 最后已知路径，仅展示 |
| `questions.<qid>.stemHash` | string | 派生 ID 的题干哈希；用于检测「题干被改」 |
| `questions.<qid>.step` | int | -1..4（§8.2） |
| `questions.<qid>.due` | string | `YYYY-MM-DD` |
| `questions.<qid>.lapses` | int | 忘记次数 |
| `questions.<qid>.reviews` | array | 最近记录，**每卡最多 20 条**（超出丢最旧） |
| `questions.<qid>.orphaned` | bool | 索引中找不到该 qid 时置 true，**不删记录** |
| `reviewLog` | array | 全局时间记录，最多 5000 条 |
| `meta` | — | 扫描时间、插件版本等诊断信息 |

> **写放大控制（C11）**：`subject/tags/source/file` 等缓存字段**仅在实际变化时**才触发 `saveData`，并做 300–500ms 防抖；未变化的索引重扫**不写盘**。
> **`reviewLog` 与每卡 `reviews`（C12）**：`reviewLog` 是全局时间记录的**单一事实源**；每卡 `reviews` 是「最近 20 条」的**派生缓存**，每次评分在同一事务内同时追加两者，二者不一致时以 `reviewLog` 为准重建。

### 9.4 索引 vs 状态的边界（再强调一次）

- **题集可见的题干/答案/笔记**：来自**实时索引**，不从 data.json 读。
- **data.json 只回答**：这题收藏了吗？练到第几档？哪天到期？练过几次？上次什么时候？
- 这样即使 `data.json` 丢失，重新索引即可重建「题目」；丢的只是历史状态（可接受）。

### 9.5 迁移机制

- 加载时读 `schemaVersion`：
  - 缺失 → 视作 `1`；结构不符合 → 进入**安全模式**（只读索引，不写状态，提示备份）。
  - 小于当前 → 依次执行 `migrate_vN_to_vN+1(pureData)`，每步纯函数、无副作用。
  - 大于当前（用户降级插件）→ **只读模式**，不覆盖，提示「插件版本过旧」。
- 每次迁移前写 `data.backup-v<old>-<timestamp>.json` 到插件目录。
- 迁移只增字段/改结构，**不丢 `reviews`/`reviewLog`**；未知字段原样保留。
- `settings` 用「深合并默认值」：缺项补默认，已有值保留。
- **首版实现范围（R6 裁剪）**：只做「`schemaVersion` 缺失/等于 1 → 正常；大于当前 → 只读 + 提示」；多级迁移函数留接口、v0.1.x 再填充，不在首版堆全量迁移器。

### 9.6 体积与裁剪

- `reviewLog` > 5000 → 从头部删除最旧，保留计数于 `meta.logTruncated`。
- 单卡 `reviews` > 20 → 丢最旧。
- 预估：5000 条事件约 0.8 MB，可接受；不做压缩。

### 10.1 令牌映射（ZapTrace 面板内）

默认**继承 Obsidian 主题变量**，另加一层 `--zt-*` 语义层；`#5854d4` **只用于控件**（开关/选中/聚焦/hover 描边），正文与标题绝不用品牌紫。

| 语义 | 默认值（跟随主题） | 可选「幕布暗色」预设 |
| --- | --- | --- |
| 面板底 | `--background-secondary` | `#212121` |
| 卡片底 | `--background-primary` | `#2c2c2f` |
| 正文 | `--text-normal` | `#d2d2d0` |
| 次要 | `--text-muted` | `#8f8f8f` |
| 标题 | `--text-normal`（加粗） | `#f2f2f2` |
| 控件强调 `--zt-accent` | `--interactive-accent` | `#5854d4` |

| 悬浮底 | `--background-modifier-hover` | `rgba(255,255,255,.09)` |

- 圆角：卡片 8px、面板 12px、控件 6px、徽标 4px。

- 投影：卡片不投影、不描边，靠底色明度差；浮层（评分条弹出、下拉）用 `0 8px 24px rgba(0,0,0,.25)`。

### 10.2 题卡组件（阅读视图）

```

│  高等数学 · 导数 · 极限                             [★]   │  头部：科目+标签，右 Star

- 折块用幕布「圆点是折叠锚点」：行首 **6px 中性灰圆点**（`#8f8f8f`）作锚点，hover 以 `box-shadow: 0 0 0 6px var(--zt-halo)` 浮出 **18px 圆盘**（180–200ms），点击折叠/展开；圆点折叠后**不变紫**，也不放大。圆点右侧接 `▸`/`▾`（旋转 200ms），整行可点，`aria-expanded` + `aria-controls`。

### 10.6 评分条（RatingBar）

```
┌──────────┬──────────┬──────────┬──────────┐
│  忘记     │  困难     │  想起     │  秒答     │

### 10.8 动效（遵循幕布 60–160ms）

| 元素 | 时长 | 属性 |
| --- | --- | --- |
| 折块展开/收起 | 160ms | `grid-template-rows 0fr→1fr` 或 max-height；箭头 rotate 200ms |
| 圆盘 hover（折叠锚点） | 200ms | 圆点 `box-shadow` 0 → `0 0 0 6px var(--zt-halo)` |
| 圆盘折叠态 | 200ms | 圆盘底色转为更实浅灰，圆点不变紫 |

@media (prefers-reduced-motion: reduce) {

    animation-duration: 1ms !important;
  }
}
```

### 10.9 亮暗主题

- 默认 `theme: auto` 跟随 Obsidian（`body.theme-dark` / `body.theme-light`）。
- 所有颜色走变量，组件不写死 `#121212` 之类暗色值；「幕布暗色」预设仅当 `theme: mubu-dark` 时覆盖令牌。
- 对比度：正文对底 ≥ 4.5:1；不用比 `--text-muted` 更暗的字承载信息（延续规范 §5.7）。
- 焦点环：`outline: 2px solid var(--zt-accent); outline-offset: 2px`，任何控件不得 `outline: none`。

### 10.10 移动端

- < 900px：三栏 → **单栏 + 底部三段切换**（练习 / 题集 / 复习），用 `role="tablist"`。
- 卡片满宽，左右 12px 边距；答案折块与评分条可滚动可见。
- 评分条固定在视口底部（`position: sticky; bottom: 0`），按钮 ≥ 44×44。
- 所有 hover 才出现的操作（Star、练习）在移动端**常驻可见**。
- 筛选条折叠为「筛选」按钮 + bottom sheet。
- 触控目标最小 44×44（含 Star、折块 chevron 的隐形命中区）。

## 14. 验收清单（可直接测试）

### 14.1 语法与解析

- [ ] 含 `### 题干/答案/个人笔记/AI 笔记` 的题卡被正确解析，四节内容各归其位。

- [ ] 手写 `id` 的题，改题干后 qid 不变、复习历史保留。

- [ ] 「插入题卡模板」只在用户触发时写入，其他任何操作不写 `.md`。

## 15. 风险与后续

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Live Preview 内交互不稳定 | 用户在编辑器里点不了 | 首版降级为缩略卡 + 工作台；文档引导「阅读视图/工作台」 |
| 自动 ID 改题干后历史断 | 复习记录成孤儿 | 推荐手写 `id`；提供孤儿迁移 |
| 重复题 / 重复 id 冲突 | 状态可能成孤儿 | `instanceKey` 索引 + §4.1 确定性隔离 + 孤儿迁移入口 |
| 大 vault 全量重扫慢 | 打开卡顿 | 首版可接受；v0.2 增量索引 |
| 用户手动改 data.json | 结构损坏 | 迁移校验 + 安全模式 + 备份 |
| 多设备同步 data.json 冲突 | 状态互相覆盖 | 文档说明；v0.2 评估按文件分片 |
| 数学公式渲染高度差异 | 卡片跳动 | 折块用 overlay 过渡，不改变文档流高度上限 |

**后续（v0.2+ 候选，需单独立项）**：CM6 实时预览 widget、孤儿状态迁移 UI、导出、按标签组卷、统计轻量页、`snooze`。

### 16.2 测试契约（Node 内置 `node:test`，非 vitest）

  - `npm.cmd test` → `node --import tsx --test tests/`
